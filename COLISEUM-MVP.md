# Coliseum battle-screen MVP

Open the website at `/#coliseum` to go directly to the arena. Choose any two
creatures, play one round with **Next round**, or run the duel with **Simulate
fight**. Playback supports 1×, 2× and 4× speed. Pause finishes the current round;
New fight cancels playback and resets the duel. Leaving the arena or hiding the
browser tab pauses combat and clears the animation.

The visual direction follows the user's [side-view arena reference](https://oyster.ignimgs.com/mediawiki/apis.ign.com/fire-emblem/d/d9/Chapter20-IMG_8304.jpg?width=640):
stone stands, a turf floor, opposing creatures, red/blue nameplates, segmented hit
bars and a compact attack readout. The arena and twelve creature-family sprites
are original SVG pixel drawings, generated by `scripts/build-coliseum-art.py`.
Family sprites represent all 130 catalog creatures; full names identify variants.

## Rules and presentation

`coliseum-rules.js` remains the combat authority. Each attack now includes its
total applied `damage`, alongside unchanged base `hits`, so the screen can show
extra critical hits and instant death accurately. Playback consumes the completed
round's events and never rolls dice or changes combat outcomes. Bleeding, missed
attacks, stun, critical severity, winner and defeat are shown from those events.
The HUD's ROLL is the modified attack total, HITS includes critical damage, and
CRIT is the delivered critical severity. OB shows the current attack's bonus
including its critical modifiers. The detailed log retains the full calculation.

`fieldbook-ui::battle_contender` renders the fighter HUD and sprite through the
existing Wasm adapter. It accepts only a presentation model and has no combat
dependencies. `coliseum-battle.js` handles browser playback and a compatible
JavaScript rendering fallback. Generic timing and Rolemaster rules remain in
their separate Rust libraries; see [RUST-MIGRATION.md](RUST-MIGRATION.md).

The battle animation is a presentation of the existing melee duel. Tactical
positions, movement, parrying and creature special abilities retain their current
arena limitations. Equipment, attacks, active effects, the rules guide and the
chronological combat log remain available below the battle screen. Existing
contender/equipment preferences keep their storage format.

## Verification

`tests/coliseum-battle-browser-smoke.js` drives the actual app with deterministic
tables. It verifies critical extra damage, bleeding, exact dice consumption,
Rust rendering, 104 Rust/JavaScript markup comparisons, sprite coverage for all
130 creatures, cancellation, pause, navigation, result banners and JavaScript
fallback with Wasm unavailable. It checks desktop and 375px/320px layouts and
the browser's reduced-motion preference. The existing Coliseum regression uses
fixed dice so its pause test cannot end randomly before the pause click.

Run this with the existing combined browser suite, `node tests/wasm-browser.mjs`.
Local visual-review artifacts are in the ignored `output/playwright/` directory.

Verified on 2026-10-15: 71 JavaScript tests, eleven native Rust tests, workspace
formatting/Clippy, and all eleven browser regressions passed. The combined run
also passed root/project-path Wasm parity and missing/delayed-Wasm startup.
Critical review remained 836 green and zero yellow. Desktop and phone screenshots
were visually inspected; the battle-specific regression reported zero page errors.
